# 权限与分享管理标准

> 适用：知识库、文档库文件、文档库文件夹、AI 工作区。代码实现见 `backend/app/services/permissions.py`。

## 一、权限模型

每个资源有一个**所有者（owner）**，并有两个开关：

| 项 | 说明 |
|---|---|
| `owner` | 资源创建者（kb/file/folder 用 `owner_id`，工作区用 `created_by`） |
| `is_private` | `true`=私有（仅 owner + 被分享者）；`false`/`NULL`=团队可见（租户内所有人只读） |
| ACL | `resource_permissions` 表，把资源分享给指定用户，权限等级 `read < edit < owner` |

**有效权限判定顺序**：owner > ACL（被分享的权限） > 团队可见（只读） > 无。

**管理员（role=admin）绕过所有 ACL**，可见并管理租户内全部资源。

## 二、文件夹：级联继承（类网盘）

文件夹是"访问容器"：**能访问某文件夹 → 其全部子文件夹及其中文件自动可见**。

- **向下递归继承**：可见文件夹的所有后代子文件夹均继承可见。
- **权限取最高**：对任一资源，有效权限 = 自身权限 与 所有祖先文件夹权限中的**最高者**。
  - 例：把父文件夹分享为 `read` → 其所有子文件夹和文件对接收者可见（`read`）。
  - 例：再单独把某子文件夹分享为 `edit` → 该子文件夹及其以下提升为 `edit`。
  - 没有"更私密"的压制机制（无法在已分享的文件夹里再把个别文件设为对分享者隐藏）。
- **写操作仍要求对应节点的权限**：删除/重命名文件夹需 `owner`；上传、移动文件到某文件夹需 `read`。

### 管理纪律（重要）
- **敏感文件不要放进已分享的文件夹**——分享文件夹 = 分享其内部全部内容。
- 需要单独保护的文件，请放到未分享的文件夹，或移出分享区。
- 已分享文件夹内的文件，其文件级 ACL 不再阻止分享接收者查看（继承优先）。

## 三、文件：与文件夹的关系

- 文件自身权限仍独立可配置（owner / 团队可见 / 单独分享）。
- 但**文件所在文件夹被分享时，文件随文件夹对接收者可见**（级联继承，见上）。
- 文件单独被分享的更高权限（`edit`/`owner`）同样生效，与文件夹继承取最高。

## 四、知识库 / 工作区

- 知识库、AI 工作区：**不参与文件夹继承**，仍为独立的资源，仅 owner/团队可见/ACL 三态。
- “我的”标识按真实 `owner_id` 判断（管理员看别人的库不会误标“我的”）。

## 五、回收站

- 软删除进回收站后，资源在回收站内仍按原权限归属；恢复即还原。
- 彻底删除时，级联关系一并清理（文件夹删除会一并清其内容）。

## 六、常见操作指引

| 目标 | 操作 |
|---|---|
| 把某文件夹开放给团队所有人只读 | 管理员/owner 打开文件夹「共享」→ 打开"对团队可见"开关 |
| 把某文件夹分享给指定同事只读 | 文件夹「共享」→ 添加用户，权限 `只读` |
| 让同事能编辑某子文件夹 | 单独分享该子文件夹，权限 `编辑` |
| 隐藏某文件不随父文件夹暴露 | 把文件移到未分享的文件夹 |
