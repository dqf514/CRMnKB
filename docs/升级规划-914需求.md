## 二、分期规划

### 一期：AI 邮件中心（最硬需求）

**目标**：客户列表选 N 人 → AI 按知识库背景生成个性化草稿 → 审阅队列逐封确认 → 发送并归档；另有按清单的分发邮件（业绩播报等）。

**数据模型**（新表）：
- `email_drafts`：id, tenant_id, customer_id, campaign_id, to_addr, subject, body_html, status(draft/approved/sent/failed/discarded), approved_by/at, sent_at, error, created_at
- `email_campaigns`：id, name, kind(personal/distribution), prompt(生成要求), source_kb_ids, status, created_by/at

**后端**：
- `POST /email-campaigns` 创建（选人/选清单 + 生成要求 + 背景 KB）
- 后台任务：逐客户生成草稿（RAG 取客户资料 + 公司介绍 + 往来记录；模板变量 {{称呼}} {{机构}} 强制逐人正确；外语记录先翻译再引用）
- `GET /email-campaigns/{id}/drafts`、`POST /email-drafts/{id}/approve|discard`、`POST /email-drafts/{id}/send`
- 发送走现有 `services/email.py`（SMTP）；发送记录归档为客户跟进记录（type=email）
- 分发模式：审阅首页样例后一键全发（仍记录每封结果）

**前端**：
- 新页面「邮件中心」（工作台侧边或客户管理下）：活动列表 → 草稿队列（左列表右预览，✓发送 / ✗作废 / 编辑后发送）→ 发送结果
- 客户详情加「写邮件」入口

**工作量**：后端 ~2 天，前端 ~2 天，联调 1 天。

**前置确认**：发件邮箱用哪个国内账号（腾讯企业邮/163 SMTP 授权码）；是否需要 DKIM/SPF（影响进箱率）。

### 二期：客户发现 Prospecting

**目标**：线索清单导入（人名+机构）→ AI research（公司网站/邮箱后缀规律；LinkedIn 提供链接不入库抓取）→ 成交概率评分 + 推荐理由 → 人工挑 5 个写 comments → 转正式客户。

**数据模型**：`leads` 表（id, name, org, email_guess, linkedin_url, research_notes, ai_score, ai_reason, status(new/researched/picked/converted/rejected), comments, created_at）

**后端**：`POST /leads/import`（Excel/文本清单）、后台 research 任务（web_search skill 已有，可直接复用）、`POST /leads/{id}/convert`（转客户 + 商机）
**前端**：「线索」页面：清单 → research 状态 → 评分排序 → 勾选转客户
**工作量**：~3 天。

### 贯穿性改造（随一期二期同步做）

1. **机构实体化**（数据模型）：
   - 新表 `organizations`（id, name, industry, address, website）+ `customer_orgs` 关联表（customer_id, org_id, position, is_current, started_at, ended_at）
   - 客户页改为「当前单位 + 历史单位」时间线；检索加机构维度；存量 customer.company 迁移为首条机构记录
   - 工作量：~2 天（含迁移）
2. **标签体系升级**：
   - 新表 `tag_dict`（id, name, dimension(customer/org/location/general), usage_count）+ 输入时词表联想勾选
   - AI 自动打标签：跟进/纪要/文档入库后，后台任务用 LLM 提取"文本明确提到的"地区/行业/主题 → 写入客户 tags + 词表计数
   - 客户列表加标签筛选（含地点）；标签云组件（ECharts 或纯 CSS 字号映射）
   - 工作量：~2 天
3. **英文界面（i18n）**：
   - 前端引 vue-i18n，菜单/按钮/表单标签抽语言包（zh/en），顶栏加语言切换（与字号/主题并列，偏好存后端）
   - 工作量大头在翻译梳理（~130 个页面字符串点位），~2-3 天
4. **客户字段补齐**：`linkedin_url`、`whatsapp`（good to have，顺手加列 + 表单/详情展示），~0.5 天

### 三期及以后（明确往后排）

- WhatsApp 字段级支持（已含在贯穿改造）；WhatsApp Business API 集成需单独评估
- 微信集成：建议走**企业微信**（官方 API 合规）；个人微信机器人有封号风险，不推荐
- Webinar：独立 project，录制→参与者→线索沉淀管线
- 邮件 DKIM/SPF 与进箱率优化（一期上线后按效果跟进）

## 三、建议落地顺序

| 批次 | 内容 | 理由 |
|---|---|---|
| **W1** | 一期 AI 邮件中心（草稿 + 审阅 + 发送 + 归档） | 客户最硬需求，最能省时间 |
| **W1 并行** | 机构实体化数据模型 + 客户字段补齐（linkedin） | 邮件的逐人称呼/机构变量依赖它，后期改代价大 |
| **W2** | 标签体系升级（词表 + AI 自动打标签 + 筛选 + 标签云） | 贯穿性，二期 prospecting 的 comments 也用它 |
| **W3** | 英文界面 i18n | 团队用英文，独立工作量 |
| **W4** | 二期 Prospecting 线索模块 | 明确排第二 |

## 五、目标升级：成为"日常工作离不开的平台"

判断标准：① 早上第一件事打开它看今天要干什么；② 工作中产生的信息随手就能进它；③ 下班/周报不用另写，它自动汇总。
现有系统已经具备"资料与 AI 能力"，缺的是**日常使用闭环**。规划如下（与一/二期正交，可并行）：

### P1 每日工作台（首页重构，最高优先）

工作台首页改为「今日」视图（现状是空白聊天区，不回答"我今天该干嘛"）：

- **今日概览卡**：今日到期任务、逾期未跟进客户、今日新增（文件/纪要/邮件）、未读通知
- **快速动作**：一键新建跟进/纪要/任务/上传（语音录音直接转写入库）
- **最近动态流**：团队今天谁在干什么（协作存在感，像群公告板）
- 数据全部已有（tasks/reminders/notifications/audit），主要是聚合查询 + 首页 UI，~2 天

### P2 全局搜索（Ctrl+K 命令面板）

- 一个入口搜全部：客户、文件、笔记、任务、邮件草稿、知识库问答
- 打开即搜、回车直达详情；这是"离不开"的关键肌肉记忆功能
- 后端聚合检索接口 + 前端 Ctrl+K 面板，~1.5 天

### P3 快速捕获（让"什么都往里丢"成为习惯）

- 工作台常驻"随手记"框：文字/截图粘贴/语音 → 自动识别所属客户（提到客户名即建议关联）→ 一键入库
- 配合同步 App（本地拖文件即入库）+ 邮件中心，形成"信息只进不出"的单一路径
- ~1.5 天

### P4 自动日报/周报（把"写汇报"消灭掉）

- 每人每日自动生成日报草稿（今日跟进/上传/任务完成/邮件发送，数据全在系统里）
- 管理者页面：团队成员日报汇总 + 周报聚合
- 定时任务 + 通知推送（复用 reminder/report 管线），~1.5 天

### P5 晨报/桌面提醒（把人拉回来）

- 每天早上系统通知 + 可选邮件晨报：今日任务、今日日程、昨天进展
- 浏览器桌面通知（Notification API，授权后即使页面在后台也能弹）
- ~1 天

### 闭环效果

```
早上：晨报通知 → 打开今日工作台（知道干什么）
白天：Ctrl+K 找一切；随手记/拖文件/写纪要（信息全进系统）
协作：动态流看到同事进展；邮件中心审批发送
下班：日报自动生成，一键确认
```

这五块做完，系统就从"工具"变成"工作本身"。建议 P1+P2 先做（感知最强），P3-P5 随后。

## 六、风险与待定项

1. **发件邮箱选型**：国内邮箱 SMTP（进箱率 vs 每日限额）；Gmail 需翻墙已确认不可行——待客户确认用哪个国内邮箱
2. **群发合规**：distribution 邮件建议加退订链接，避免被标记垃圾邮件
3. **自动归入客户知识库**：需求里客户自己也说"待方案明确"——建议一期先保持手动关联，二期做"按发件人/内容 AI 建议归属 + 一键确认"
4. **会议纪要必填**：产品上靠流程（提醒规则已有：可加"会后 24h 无纪要提醒"），技术上已具备
5. **转写稿核对**：本整理稿基于离线转写，个别专名（如"杨一南"）建议回听 `24:23–26:22` 段核对
